# 타오바오 — 폰에서 담고, PC에서 마무리

## 실측이 닫은 문 (2026-09-11, 상하이 · 오너 아이폰)

| 무엇을 | 어디서 | 결과 |
|---|---|---|
| `e.tb.cn` 단축 링크 | **중국 IP** | 리다이렉트만으로 최종 URL에 `id`·`price`·`tk` 실림 — **로그인 불요** |
| `e.tb.cn` 단축 링크 | VPN 켬 · **해외 IP** | **연결 거부** |
| `m.intl.taobao.com` 상세 | VPN 온(+82) / 오프(+852) | **IP 무관 로그인 벽** |

→ **서버측 타오바오 경로는 0입니다.** 코드도 플래그도 두지 않았습니다.
실측이 닫은 문 앞의 "혹시" 코드는 보험이 아니라 **부채**입니다 —
끈 채로 남기면 다음 사람이 켜 보고 같은 실패를 다시 겪습니다.

**폐기:** 서버 해석기 · 폰 fetch · 게스트 mtop h5.

## 동작하는 흐름

```
폰(중국망): 타오바오 앱 → 공유 → 단축어「URL 확장」
                ↓
        제목 · 상품번호 · 가격(CNY) · 링크 저장
                ↓
PC(로그인된 타오바오 탭): 고가수집기 → 이미지 · 옵션 보강 → 등록 가능
```

**펴는 일은 폰이 합니다**(중국망에 있으니까).
**나머지는 확장이 합니다**(로그인 세션이 그 브라우저에만 있으니까).

## 두 갈래 — 화면이 어느 쪽인지 말합니다

| 폰이 폈나 | 담기는 것 | 아직 없는 것 | 마켓 등록 |
|---|---|---|---|
| ✅ 폈다 | 제목 · 상품번호 · **가격** · 링크 | 이미지 · 옵션 · 상세 | **가능** |
| ❌ 못 폈다 | 제목 · 링크 | 가격 · 이미지 · 옵션 · 상세 | 닫힘 |

### 왜 못 폈는지는 말하지 않습니다 (C-F9-1, 2026-09-12)

옛 문구는 VPN 설정 때문이라고 **단정**했습니다 — 게다가 **존재하지 않는 앱 모드 이름**을 들며.
그런데 오너 실측에서 **VPN이 꺼진 채로** 같은 결과가 나왔습니다 — 단정이 그대로 오진이 됐습니다.

서버는 폰의 VPN·통신사·앱 상태를 **볼 수 없습니다.** 볼 수 있는 건 셋뿐입니다:

| `resolve_gap` | 서버가 본 것 |
|---|---|
| `ok` | 가격이 왔다 |
| `no_final_url` | **펴진 링크가 아예 안 왔다** |
| `final_url_without_id` | 펴진 링크는 왔는데 거기 상품번호가 없었다 |
| `id_without_price` | 상품번호는 왔는데 가격이 없었다 |

화면은 이 넷만 말합니다. 원인은 **「링크 진단」**이 실제로 재서 말합니다.

### VPN 앱 모드 이름은 세 번 다 발명이었습니다 (오너 실측 2026-09-12)

아스트릴 iOS **2.3.8** 화면에 있는 것: **ON/OFF · 서버 · TCP/UDP · Always On · Reconnect.**
**모드 선택이라는 것이 없습니다.** 그런데 안내 문구는 모드 이름을 세 번 갈아 댔습니다 —
`Smart` → `전체(Global)` → `규칙`. 전부 **측정한 적 없는 이름**입니다.

없는 UI를 가리키는 안내는 틀린 안내보다 나쁩니다 — 유저가 **찾다가 자기를 의심**합니다.

허용되는 문장은 **한 종류**뿐입니다: 「VPN이 켜져 있으면 끄고 다시 시도해 주세요」.
스위치는 실제로 그 화면에 있습니다(ON/OFF). 그리고 이 문장조차 **서버가 실패 원인을 실측한
갈래에서만** 씁니다 — 서버는 폰의 VPN을 못 보므로, 지금 서버 응답에는 **한 번도 쓰이지 않습니다.**

아는 사실은 하나뿐입니다 — 해외 IP에서 `e.tb.cn`은 **연결 거부**(실측 2026-09-11).

**가격은 공유한 그 순간의 값입니다** — 실시간 시세가 아닙니다. 화면에 그렇게 표시됩니다.

## 등록 게이트

가격이 없으면 **서버가** 마켓 등록을 막습니다(버튼만 숨기는 게 아닙니다).
게이트는 **가격이 실제로 도착했을 때만** 열립니다 — 이미지·옵션만 채워져도 닫힌 채입니다.
마진을 낼 수 없는데 0으로 채우면 그건 계산이 아니라 날조입니다.

## 단축어 만들기 (v2)

**단축어 앱 → 새 단축어 → 공유 시트에서 받기 켜기**(입력: URL **및 텍스트**)

| 순서 | 동작 | 설정 |
|---|---|---|
| ① | **URL 확장**(Expand URL) | 입력 = 공유된 항목 |
| ② | URL 콘텐츠 가져오기 | `https://<도메인>/api/v1/collect/one` · POST · `Authorization: Bearer <토큰>` |
| | | JSON: `url` = 공유된 내용 그대로 · `final_url` = ①의 결과 |
| ③ | 결과 보여주기 | `message` |

> ①이 실패해도 **수집은 됩니다** — 제목과 링크만 담기고 가격·상품번호가 비는 것뿐입니다.
> 어느 쪽인지 답이 알려 줍니다(`resolve_gap`). 실패 원인은 「링크 진단」에서 확인하세요.

### 쓰는 법

타오바오 앱 → 상품 → **공유 → 링크 복사** → 단축어 실행.
또는 공유 시트에서 바로 단축어를 고르셔도 됩니다.

### 돌아오는 답

```json
{ "ok": true, "partial": true, "item_id": "…", "title": "…",
  "price": "199", "currency": "CNY", "item_id_taobao": "993154784090",
  "uncollected": ["images", "options", "description"],
  "message": "제목·상품번호·가격까지 담았어요(공유 시점 가격). 이미지·옵션은 PC에서 고가수집기로 보강해 주세요." }
```

링크가 안 펴졌다면 `price`가 비고 `uncollected`에 `price`가 함께 들어옵니다.

## 「링크 진단」 — 302 체인을 서버가 스스로 잰다 (C-F9-3)

F7-2는 「Render 싱가포르에서 `e.tb.cn` 302 체인을 재라」였고, 그동안 **사람 손**을 기다렸습니다
(CC 샌드박스 프록시가 그 도메인을 막습니다 — `CONNECT tunnel failed`, 대조군 github는 200).

측정을 사람 손에 맡기면 **매번** 사람 손이 필요합니다. 그래서 앱 안에 재는 자리를 뒀습니다:

| 어디서 | 인증 |
|---|---|
| 콘솔 **「링크 진단」** `/seller/collect/link-diag` | 로그인 세션(폰에서도 바로) |
| API `POST /api/v1/collect/link-diag` | Bearer 토큰(단축어·확장) |

돌려주는 것 — **원문입니다, 요약이 아닙니다**: 홉마다 상태코드와 `Location`, 최종 주소,
거기서 뽑은 상품번호·가격, 실패면 **예외 클래스명과 메시지 그대로**.
그리고 **「우리가 저장하는 형태」를 나란히** 보여 줍니다 — 두 줄의 차이가 우리가 일부러 버리는
값(기기 UUID·세션 서명)입니다.

### UA 2종을 각각 잽니다 (F10-2)

타오바오는 **UA로 응답을 가릅니다.** 한 가지로만 재면 「막혔다」가 *우리 서버 위치* 때문인지
*UA* 때문인지 **구별이 안 됩니다** — 구별 안 되는 측정으로 원인을 말하면 그게 F9-1에서 걸린
바로 그 단정입니다. 그래서 두 번 재서 둘 다 보여 줍니다:

| 이름 | UA |
|---|---|
| **기본** | **미지정**(라이브러리 기본값) — 가려지지 않은 쪽이 있어야 비교가 됩니다 |
| **iOS Safari** | 오너가 실제로 성공한 환경 |

둘의 결과가 다르면 화면이 그대로 말합니다 — 「UA에 따라 응답이 달랐습니다」.
요약 숫자는 **가장 멀리 간 측정**의 것이고, 어느 쪽이었는지 함께 적습니다.

### 최종이 200이면 본문도 봅니다 (F10-1)

최종 URL 쿼리에 `id`가 없어도 **본문에 상품 링크가 박혀 있을 수 있습니다**(안내·중간 페이지).
그걸 안 보고 「상품번호 없음」이라 말하면 **덜 보고 단정한 것**입니다. 그래서 본문에서
상품 도메인 링크와 `id=` 숫자를 찾아 `body_item_url`·`body_item_id`로 **따로** 돌려줍니다.

**섞지 않습니다** — 주소에서 읽은 값과 본문에서 찾은 값은 출처가 다르니 신뢰도도 다릅니다.
화면도 「주소의 상품번호」·「본문의 상품번호」로 나눠 보여 줍니다.

못 찾으면 **계량값만** 적습니다: 본문 길이 · `<title>` · `<script>` 개수.
짧고 스크립트가 많으면 JS로 그리는 빈 껍데기, 제목에 로그인이 보이면 로그인 벽입니다.

**저장 0.** 진단 결과는 이력·DB에 남기지 않고, 로그엔 호스트·상태코드·상품번호 유무만 남깁니다.
**본문 원문은 반환도 저장도 로그도 하지 않습니다** — 길이·제목·스크립트 수라는 계량값만 냅니다.
**허용목록**(타오바오 계열)만 진단합니다 — 안 걸면 이 라우트가 열린 프록시가 됩니다.

| 진단이 이러면 | 뜻 |
|---|---|
| 주소에서 상품번호·가격 확보 | **서버가 펼 수 있다** → 폰 단축어 없이도 담을 수 있다 |
| **본문에서** 상품 링크 발견 | 한 홉만 더 가면 상품이다 → 체인을 한 번 더 따라가는 설계가 가능 |
| 펴졌는데 본문에도 없음 | 로그인 벽이거나 JS로 그리는 빈 셸(계량값이 어느 쪽인지 말해 준다) |
| UA에 따라 결과가 갈림 | 막힌 원인이 **서버 위치가 아니라 UA**다 |
| 양쪽 다 연결 거부·타임아웃 | 우리 서버 지역에서 막혔다 → 지금 구조(폰이 편다)가 정답 |

**이 결과와 무관하게 현재 경로는 동작합니다** — 제목만으로 초안이 서고,
가격·ID는 폰이 펴 줄 때 담깁니다. 체인이 열리면 그때 **한 겹 더 좋아지는** 것뿐입니다.

## 서버가 단축 링크를 편다 (C-F11, 오너 실측 2026-09-12)

**실측이 닫았던 문을 실측이 다시 열었습니다.**

| 무엇을 | 결과 |
|---|---|
| `e.tb.cn` (Render 싱가포르, **UA 무관**) | **200** |
| 그 본문 | `item.taobao.com/item.htm?…&id=1060535477134&price=76.86&…` |

F9까지 「서버는 타오바오를 못 읽는다」고 적은 건 **리다이렉트 쿼리만 봤기 때문**입니다.
쿼리엔 `id`가 없었고 **본문에는 있었습니다** — 덜 보고 닫은 문이었습니다.

### 그래서 수집이 이렇게 바뀝니다

```
단축 링크 1개 (제목도 없어도 됨)
      ↓  서버가 한 번 펴 본다(6초 예산)
상품번호 1060535477134 + 공유 시점 가격 76.86 CNY
      ↓  URL은 정규형으로 저장 — https://item.taobao.com/item.htm?id=1060535477134
초안: uncollected = images·options·description  (price 탈락)
      ↓  가격이 있으니 **등록 게이트 열림**
```

- **펴는 일만** 합니다. 상세·이미지·옵션은 여전히 로그인 벽 뒤이고(실측 불변) 확장 몫입니다.
- **폰이 이미 펴 줬으면 다시 나가지 않습니다**(같은 값을 두 번 재지 않습니다).
- 예산 **6초**(진단은 10초). 수집은 요청 안에서 도는 코드라 W10의 워커 점유 흉이 그대로 적용됩니다.
- 끌 수 있습니다: `KGP_SHORT_LINK_RESOLVE=0`. 테스트는 conftest가 기본 OFF로 고정합니다 —
  계약이 네트워크를 재기 시작하면 그건 계약이 아닙니다.
- 정규형은 **추적 파라미터를 하나도 안 남깁니다**(`spm`·`tk`·`un`·`suid`…). 같은 상품이
  단축/편 링크 어느 쪽으로 담겨도 **한 키로 합쳐집니다**.

### 실패 갈래는 그대로 실립니다 (`resolve_gap`)

| `reason` | `resolve_gap` | 뜻 |
|---|---|---|
| `ok` | `ok` | 상품번호·가격 확보 |
| `no_item_in_body` | `server_opened_no_item` | **200인데 본문에 상품 링크가 없다** |
| `http_<코드>` · `error:<예외>` | `server_could_not_open` | 열지 못했다 |
| `disabled` · `not_short_link` | (실패 아님) | **안 해 본 것은 실패가 아니다** |

원인을 짐작해 붙이지 않습니다. 200인데 본문이 빈 것과 아예 못 연 것은 **다른 사실**입니다.

## 보강 소비자 — 실측 먼저 (C-F11-4, 코드 없음)

F9-2가 찾은 세 겹 막힘 중 **1번(가격)은 위 해석으로 풀렸습니다.** 남은 것:

2. `GET /api/v1/collect/enrich/pending`의 **소비자가 0** — 확장이 폴링하지 않습니다.
3. ~~초안 `url`이 `e.tb.cn`이라 확장도 못 엶~~ → **해소**: 이제 정규형 `item.taobao.com`으로 저장됩니다.

그래서 남은 질문은 **하나**로 줄었습니다:

> **로그인 없는 상태에서 `item.taobao.com/item.htm?id=…`가 이미지·옵션을 주는가?**

주면 확장 폴링 구현이 곧바로 의미가 있고, 안 주면 「로그인된 탭에서만」이라는 제약이
설계를 바꿉니다(사용자가 타오바오에 로그인해 둬야 한다는 안내가 필요해집니다).
**재기 전엔 코드를 쓰지 않습니다** — 이 트랙에서 추측 설계로 네 번 헛돌았습니다.

### 실측 방법 (오너 PC, 1회 · 2분)

정규형 URL 하나로 두 번 비교합니다. **로그아웃 상태를 만들 필요는 없습니다** —
시크릿 창이 로그인 없는 상태입니다.

```
① 일반 창(타오바오 로그인된 상태)에서 열기
   https://item.taobao.com/item.htm?id=1060535477134

② 시크릿 창(Ctrl/Cmd+Shift+N)에서 같은 주소 열기
```

각 창에서 **F12 → Console**에 붙여넣고 나온 숫자를 적어 주세요:

```js
JSON.stringify({
  제목: (document.querySelector('h1,[class*=title]')||{}).innerText?.slice(0,40) || '',
  큰이미지: [...document.images].filter(i=>i.naturalWidth>=250).length,
  옵션칸: document.querySelectorAll('[class*=sku] li,[class*=SkuContent] [class*=valueItem]').length,
  주소: location.hostname + location.pathname,
})
```

| 회수할 것 | 왜 |
|---|---|
| ①②의 `큰이미지` 수 | 0 vs n → 로그인이 이미지를 가르는지 |
| ①②의 `옵션칸` 수 | 옵션 추출 가능성 |
| ②의 `주소` | 로그인 페이지로 **튕겼는지**(호스트·경로가 바뀐다) |

**②에서 이미지가 n장 나오면** → 확장 폴링을 구현합니다(콘솔 열릴 때 대기 목록 조회 →
백그라운드 탭에서 정규형 URL 열기 → tier1 추출 → 기존 `/enrich`로 POST).
**②가 0이거나 로그인 페이지로 튕기면** → 「타오바오에 로그인된 브라우저에서만 보강됩니다」를
화면이 먼저 말하게 하고, 그 전제로 폴링을 짭니다.

## 淘口令·tk로 상품번호를 얻을 수 있나 (C-F9-4) — 아니오

실측으로 확인된 것만 적습니다.

| 값 | 실측 | 상품번호를 얻을 수 있나 |
|---|---|---|
| `sp_tk` | `bnlYcFQ3VkE3bHQ=` → base64 디코드 → `nyXpT7VA7lt` = **`tk`와 완전히 동일** | ❌ tk를 복원할 뿐 |
| `tk` (`nyXpT7VA7lt`) | base64로 읽으면 8바이트 난수(`9f 25 e9 4f b5 40 ee 5b`) | ❌ 상품번호 없음 |
| 淘口令 (`CZ356`·`HU591`) | **base64가 아니다**(디코드 실패) | ❌ 앱 전용 코드 |

`tk`·淘口令은 **타오바오 서버에 물어봐야 뜻이 생기는 조회 토큰**입니다. 로컬 파생은 불가능합니다.
그 조회를 하는 HTTP 엔드포인트는 **우리가 측정한 바가 없어 적지 않습니다** — 추측으로 주소를
만들어 넣는 것이 이 트랙에서 네 번 반복된 실패(발명 경로)입니다.

**실측 가능한 유일한 길은 「링크 진단」**입니다: 링크를 따라가 최종 URL에서 `id`를 읽는 것.
이미 동작하는 원리(폰이 하는 일)를 서버가 할 수 있는지 재는 것이므로 발명이 아닙니다.
