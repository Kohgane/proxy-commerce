# Z3-L — 로그인 쿠키 경로 (설계 메모, 구현하지 않음)

오너 지시(2026-10-05): **Z3-L은 구현하지 않는다.** 이 문서는 설계만 남긴다. 쿠키 이름은 실측한 뒤에 적는다(추측 금지).

## 왜 필요한가
- 오너 실측(프록시·폰 LTE·집 PC 모두 같음): set_x5referer 1·2차는 HTTP 200 · 본문 987자 · x5secdata 받음,
  3차 getdetail은 다시 1단계 스크립트. 본문 스크립트가 `login_jump` → `loginUrl + uuid + "&redirectURL=" + login_jump`로 보냄.
- 결론: **익명 세션을 받지 않는다(IP 무관).** IP를 바꾸는 방법(relay2·주거 프록시)으로는 안 풀린다.
- 지금 대안은 외부 공급자 API(Z3-B, `TAOBAO_DETAIL_PROVIDER=onebound`). Z3-L은 그게 막히거나 비쌀 때의 두 번째 길이다.

## 생각하는 흐름 (실측 전 — 확정 아님)
1. 오너가 자기 타오바오 계정으로 폰/PC 브라우저에 로그인한다.
2. 그 세션의 쿠키를 서버로 옮긴다(방법은 미정 — 확장 export 버튼 또는 진단 화면 붙여넣기).
3. mtop 호출에 그 쿠키를 싣고 `_m_h5_tk` 토큰 왕복 → getdetail.
4. 쿠키가 만료되면 「다시 로그인」 안내 + 그 건은 (c) 수동 카드.

## 실측으로 먼저 정해야 하는 것
- **어떤 쿠키가 있어야 getdetail이 JSON을 주는가** — 이름 목록. 로그인 직후 브라우저 쿠키 전체를 진단 화면에 붙여 넣고,
  하나씩 빼 보며 최소 집합을 잰다. (지금 코드가 아는 이름은 `_m_h5_tk`·`_m_h5_tk_enc`·`x5sec*` 뿐 — 로그인 쿠키는 모른다.)
- 쿠키 수명(몇 시간·며칠)과, 서버 IP(Render·relay2·프록시)에서 같은 쿠키를 써도 되는지(IP 바뀌면 끊기는지).
- 한 계정으로 하루 몇 건까지 조용한지(계정 제재 위험).

## 지킬 것
- 쿠키 값은 로그·화면에 남기지 않는다(글자 수만, 지금 `_mask`와 같이). 저장은 Fernet 암호화(마켓 키와 같은 방식).
- 오너 계정 하나만. 다른 셀러 계정 쿠키를 모으는 기능은 만들지 않는다.
- 막히면 조용히 재시도하지 않고 (c) 수동으로 — 지금 자동 경로 규칙과 같다.

## 상태
- 구현하지 않음. 쿠키 이름·수명 실측이 끝나면 별도 브리프로.
