# 콘솔 이원화 판단 보고 (v87-S4 · 수정 없음, 사실 조사만)

오너 요청: `/dashboard/` 와 `/seller/` 의 역할 구분, 각각의 진입 경로·인증 상태·중복 화면 목록.
**통합/분리 결정은 오너.** 이 문서는 코드에서 확인한 것만 적는다.

## 1. 한 줄 요약

두 콘솔은 **같은 데이터를 다른 화면으로 두 번 보여주고 있다.** 인증 기준이 다르고(관리자 vs 로그인 유저),
디자인 시스템이 다르고, 링크로 서로 이어져 있지 않다. `/dashboard/` 는 **사이드바 어디에도 링크가 없어**
주소를 직접 알아야 들어간다.

## 2. 규모·인증

| | `/dashboard/` | `/seller/` |
|---|---|---|
| 라우트 수 | **10개** | **202개** |
| 인증 | `is_admin_session` — 미로그인 302, 비관리자 **403** (v87-S1.5 deny-by-default) | `_check_auth()` — 로그인 세션만 확인(`SELLER_CONSOLE_AUTH=1` 기본) |
| 응답 헤더 | `no-store`(PCC·고객명 렌더 화면) | 일반 |
| 렌더 방식 | `web_ui.py` **단일 파일** + `render_template_string` | Jinja 템플릿 40+ |
| 디자인 | v87 `kgp-*` 토큰(먹/한지/금) | `console.css` + Bootstrap, 청록 테마 |
| i18n | **없음**(전부 하드코딩 한국어) | `t()` + `kgp_lang` 쿠키(ko/en) |
| 파비콘 | v87-S4에서 추가(그 전엔 **선언 0**, 루트 폴백) | `?v=` 캐시버스트 있음 |

**→ 역할 구분은 "관리자 vs 유저"가 맞다**(인증 기준이 그렇게 갈려 있다). 다만 그 의도가 화면에 드러나지
않는다 — `/dashboard/`에 "관리자 전용"이라는 표기가 없고, `/seller/`에서 넘어가는 링크도 없다.

## 3. 진입 경로

- `/seller/` — 랜딩 CTA(`/seller/`), 콘솔 브랜드 로고, 사이드바 전체. **정상 진입 동선 있음.**
- `/dashboard/` — **인바운드 링크 0.** 랜딩·셀러 사이드바·탑바 어디에도 없다(`grep "/dashboard/"` = 0건).
  주소를 직접 치거나 북마크로만 도달한다.

이게 "별도 생존"으로 보이는 이유다. 죽은 화면은 아니고(라우트·인증 정상 동작), **발견 경로가 없는 화면**이다.

## 4. 중복 화면 목록

| 주제 | `/dashboard/` | `/seller/` | 데이터 소스 |
|---|---|---|---|
| 한눈에 보기 | `/dashboard/` | `/seller/dashboard` | 같음(주문 PG + 수집 PG) |
| 주문 | `/dashboard/orders` | `/seller/orders` | **같음**(`orders` 테이블) |
| 수집 상품 | `/dashboard/products` | `/seller/collect/history` | **같음**(`collect_history`) — v87-S3에서 소스 통일 |
| 업로드 이력 | `/dashboard/uploads` | `/seller/markets` | 같은 Sheets `upload_history` |
| 환율·마진 | `/dashboard/fx` | `/seller/pricing` 계열 | 같음(`compute_sell_price`) — v87-S4에서 식 통일 |

**5개 주제가 전부 겹친다.** `/dashboard/`의 10개 라우트 중 화면은 5개고, 그 5개가 모두 `/seller/`에 대응
화면을 갖고 있다. 나머지 5개는 액션·JSON(`/summary`·`/collect/start`·`/upload/run`·`/fx/policy*`)이다.

## 5. 판단 재료 (결정은 오너)

- **겹침이 우연이 아니다.** v87 STEP1~S4가 `/dashboard/`를 새 디자인으로 다시 지으면서, `/seller/`의
  같은 화면은 그대로 뒀다. 지금 상태를 유지하면 **버그도 두 번 고쳐야 한다** — 실제로 이번에 주문 소스
  (#562)·수집 소스(#568)·가격 식(S4)이 각각 한쪽만 낡아 있던 걸 고쳤다.
- **언어 혼재의 진짜 원인이 여기다.** `/seller/`는 EN 토글이 먹지만 `/dashboard/`는 i18n이 없어 항상
  한국어다. 문자열을 채워도 두 콘솔이 남아 있는 한 EN 모드는 반쪽이다.
- 선택지는 셋으로 보인다:
  1. **`/dashboard/`를 관리자 전용으로 명시**하고 셀러 콘솔에서 링크 노출(현 구조 유지, 발견 경로만 추가).
  2. **`/seller/` 화면을 `/dashboard/` 디자인으로 이관**하고 `/dashboard/`는 관리자 진단만 남김.
  3. **`/dashboard/`를 접고** v87 작업분을 `/seller/`로 흡수.
- 어느 쪽이든 **이번 S4 수정분(계산기·칩·파비콘·언어)은 그대로 살아남는다** — 전부 `/dashboard/` 쪽
  결함 수리이거나 공용(파비콘·i18n) 계층이다.

## 6. "코" 아바타 — 아이콘 아님

`/seller/` 워크스페이스의 "코"는 이미지가 아니라 **텍스트 이니셜 배지**다
(`_base.html`: `(_user_name or _user_email or '나')[:1]|upper`). 계정 표시명 첫 글자를 그대로 쓴다.
비마스터 아이콘 잔존이 아니므로 아이콘 통일 작업 대상이 아니다 — 바꾸려면 별도 디자인 결정이 필요하다.

## 7. 비마스터 아이콘 스캔 결과

`src/` 전 템플릿의 아이콘 참조를 훑은 결과 **비마스터 아이콘 파일 참조는 0건**이다.
favicon.svg/ico·favicon-16/32/48·apple-touch-icon·icon-192/512/1024·og-card가 전부
`assets/brand-icons` 마스터에서 파생된 같은 파일을 가리킨다. 캐시버스트 값도 `v=183`으로 단일하다.
