# v87-W1 — 수집 목록 위생: 비상품 정리 후보 + 유입 봉인

수집 경로로 잘못 유입된 비상품 페이지(iCloud Mail·ChatGPT·검색·문서 등)를 **후보로만** 제시하고,
정리는 **보관(복원 가능)**을 기본으로 한다. 자동 삭제는 어디에도 없다.

## 금지 구조(본체)
- **자동 삭제 절대 금지.** 판별기는 후보 제시까지만(부수효과 0 — 가드로 못박음).
- 기본 동작 = **보관(archive, 복원 가능)**. 영구 삭제는 **‘보관’ 목록에서만 + 2단 확인**(체크박스).
- 실행 전 대상 목록 전량 제시(‘정리 후보’ 탭에서 확인 후 선택).
- 실유저 데이터 대상 → 비가역. **오탐으로 실상품을 거부/삭제하지 않는다(오탐 0 최우선).**

## 판별기 (src/seller_console/collect_hygiene.py — 서버 트랙, 확장 불가침)
점수+사유를 남기는 고한계 휴리스틱(돈 걸린 매칭과 동일 원칙):
- **쇼핑 도메인(temu·amazon·aliexpress·rakuten…)은 early-return → 절대 후보 아님.** 추출 실패로
  필드가 비어도 상품으로 간주(거부보다 미검출 선택). → **실상품 오탐 0 보증.**
- (A) host가 명백한 비쇼핑 서비스(메일·챗/AI·문서·클라우드·검색·SNS·개발·뱅킹) → 확정 후보.
- (B) 쇼핑도 비쇼핑목록도 아닌 host인데 가격·이미지·옵션 전무 + 상품 URL 마커 부재 → 보수적 후보.
- 한계 70점. 놓친 건 정직하게 미검출로 둔다(오탐보다 미검출을 택함).

## UI (collect_history)
- **‘정리 후보 보기’** 진입 + 필터(`?hygiene=cleanup`) — 후보만 표시.
- 안내 배너: “삭제가 아니라 **보관(복원 가능)**. 영구 삭제는 ‘보관’ 목록에서만, 다시 확인 후.”
- 후보 행 배지 **‘비상품 의심’**(사유 툴팁) — 일반 목록에서도 표기(유입 봉인 가시화).
- **‘선택 보관(복원 가능)’** 버튼(기본 정리 동작). 정리 후보 뷰에선 영구 삭제 버튼 숨김(archive-first).
- 영구 삭제 모달에 **2단 확인 체크박스**(‘되돌릴 수 없음 동의’) — 체크해야 삭제 활성.

## 유입 봉인 (extension_api 저장 시점)
저장 시 같은 판별기 통과 → 후보면 `extra.hygiene`에 점수/사유 기록 + 응답 `hygiene_warning`으로
경고. **저장 자체는 허용**(오탐으로 실상품 거부 금지).
