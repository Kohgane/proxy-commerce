## item 1 — 번역 토글: 전 구간 감사 + 표시
- **감사 결과 배선은 온전**: 팝업 `kgp_translate`(기본 ON) → background `_kgpWithTranslateFlag`가 OFF일 때만
  `translate:false` 첨부 → 서버 `translate = payload.get("translate", True) is not False`로 **존중**. 끊긴 지점
  없음(토글→payload→서버 respect).
- **체감 불일치의 실체 = item 2와 동근**: 번역 **실패** 시 원문 유지인데 응답이 `translated=True`로 보고
  (폴백을 성공으로 오분류) + 실패 사유 미저장 → "번역 ON인데 원문" = "토글 무시"로 오인. → **레코드 단위
  상태 3분**(번역함/원문(사용자 선택 안 함)/실패)으로 정직 표시.

## item 2 — 번역 실패 조사 (계측 수치 필수)
### 계측 (호출 n·실패 n·사유별)
`translator._record_translate` + `get_translate_stats()` 신설(**쿼터 회계와 별개 읽기전용** — 무손대).
로컬 재현 실측(모킹, 실 API 호출 0 = AI 예산 존중):
```
1) 긴 일본어 상세(721자급) 번역 → provider=openai-fallback, error="번역 API 호출에 실패했어요",
   title_ko==원문(유지).  계측: {calls:1, ok:0, fail:1, by_reason:{"번역 API 호출에 실패했어요":1}}
2) 정상 1건 추가 →                     계측: {calls:2, ok:1, fail:1, by_reason:{…:1}}
```

### 근원 (실패 다발)
`_translate_openai` **max_tokens=900 고정**이 **긴 상세(일본어 721자) + 제목 + 마켓 카피 3종**을 한 JSON으로
뽑을 때 출력을 잘라 `json.loads` 실패 → `openai-fallback`(원문 유지). = "됐다는데 원문"의 정체. 긴 텍스트
분기가 **조용한 실패 다발**의 본체.

### 수리
- **근원**: `max_tokens = max(900, min(3000, 1000 + 입력길이))` + 타임아웃 길이대응(>400자 → 30s). AI 예산
  존중(캡 3000). 721자 케이스: 900 → ~1721 토큰으로 잘림 해소.
- **정직 표시**: `_extra`에 `translated`(폴백·stub·none 제외 실제 번역만) / `translate_error`(사유) /
  `translate_requested`(토글) 저장. 응답 `translated`도 폴백=실패로 정정. 재수집=번역 재시도로 상태 갱신.
  - **목록**: `번역 실패`(적, 클릭→드로어 재번역) / `원문(번역 안 함)`(회색, 사용자 선택) / `원문`(미번역).
  - **드로어**: 실패 사유 + `다시 번역` 버튼(기존 `한국어로 번역`=재시도).
