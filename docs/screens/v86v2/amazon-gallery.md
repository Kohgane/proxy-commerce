# v86-V2 — 아마존 상세 갤러리 대표 1장 → n장 (실기기 재현·수리)

## 오너 확정 사실 (재조사 금지)
1.5.145 amazon dp(SUPERONE) single·adapterMatched=True: gallery=**1장**(대표 713q1zpatL만). DOM 실측:
#altImages 존재·썸네일 버튼 7·썸네일 ID 다수 — 소재는 있는데 수집이 안 집는다. v86-V 2항의 "실추출 og 1 +
#altImages 5 → ≥5장"은 오너 환경에서 **재현 안 됨**(공허한 그린).

## 완료 4항

### 1) 실크롬 재현 + 근원 특정
`_amazonGallery`의 **`naturalWidth < 40` 가드**(1px·아이콘 배제용)가 아마존 정품 썸네일(디자인상 `_AC_US40_`
= ~38px 렌더)을 **7장 통째로 배제** → 대표 1장만 생존. 실크롬(38px 실로드 `_AC_US40_` 썸네일)에서 수리 前
gallery=**1**, 수리 後 **8**. (data: 지연 placeholder는 복구할 URL 자체가 없어 1 유지 — 오너 '썸네일 ID 다수
in DOM' = 실 URL 존재 → naturalWidth 가드가 원인.)

### 2) 근원 수리 + 계약을 오너 재현 조건으로 재작성 + 부검
- **수리(extractor DOM 갤러리만 — tier1/kgp-net 무수정)**: 크기 토큰(`_AC_US40_` 등)이 있어 hiRes가 대형
  원본으로 승격하는 URL(`hr !== src`)은 **크기 가드를 건너뛰고**, 토큰 없는 고정크기 이미지에만 1px/아이콘
  가드 적용. 판별은 썸네일 렌더 크기가 아니라 **승격 URL(hr)의 상품성**으로(= `_bestImgSrc` 설계 일치, 신규 발명 0).
- **계약(`tests/test_v86_v2_amazon_gallery.py`)**: 오너 재현 조건으로 재작성 — 썸네일을 **실제 38px로 로드**
  (media-amazon 이미지 라우트로 실 PNG 응답 → naturalWidth=38, 옛 가드 발동)해 그 분기를 실브라우저로 강제.
  수리 後 갤러리 ≥8 + **가드 판별**(크기 토큰 없는 38px 아이콘은 여전히 배제 = 가드 미제거·오탐 0).
- **부검 1줄**: v86-V 계약은 썸네일을 비로드(naturalWidth=0)로 픽스처링해 `naturalWidth<40` 가드가 우회됐고,
  실기기의 **로드된 38px 썸네일** 분기(가드 발동)를 실브라우저로 강제하지 않아 false green이 났다.

### 3) echo (dp payload_echo=null)
**오너 답변 대기 중** — "수집 이벤트가 실제로 있었나" 확인 1건이 걸려 있다. 답이 "수집했다"면 dp 팝업 echo
경로를 이 트랙에서 계측·수리하고, "안 했다"면 echo 항은 제외한다. 답 오기 전까지 **갤러리 건을 본체로 완결**
(브리프 지시). → echo 항 이번 보고 **보류**.

### 4) 최종 판정 = 오너 dp 재수집
확장 **1.5.146 재로딩** 후 amazon dp 재수집 → 갤러리 **n장**(대표+썸네일) 확인. (echo 충전은 오너 답변 후.)
