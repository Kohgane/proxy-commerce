# v87-W5 — AI 상세 초안 생성 품질: 번역 이상 수리

## 오너 실기기 확정 사실 (재조사 금지)
라쿠텐 TSUMUGI 레코드(일본어 원문 상세, 721자)에서 [AI 상세 초안 생성] → "번역이 되는데 좀 이상함".
언어 원칙(불변): KO/EN(JP) 혼재 금지. 초안은 **판매용 한국어 문안**이 기대치(원문 직역 덤프 아님).

## 1) 실재현 + 생성 경로 감사
- 경로: `POST /seller/collect/preview/<id>/ai-description` → `AITranslator.generate_description({title, category,
  keywords, specs(=detail_specs+options), brand})` → 키 있으면 `_describe_openai`(OpenAI), 없으면 `_structured_draft`(stub).
- **재현(TSUMUGI 모사, stub)**: 특징에 `レビューを見る`·`送料無料`, 옵션·상세에 `不適切な商品を報告`·`レビュー`·
  `お気に入り`(라쿠텐 UI 쓰레기) + 일본어 스펙(サイズ/素材/原産国) **그대로**. = 오너 "번역이 이상함" 재현.

## 근원 (2갈래 특정)
1. **입력 오염 미제거** (branch ③): 라쿠텐 UI 문구가 detail_specs/keywords에 섞여 프롬프트·초안에 유입.
   `_CONTAM_RE`는 확장/브라우저 크롬만 잡고 **마켓 UI 쓰레기(특히 일본어)는 미포함**, 스펙엔 오염 필터 **아예 미적용**.
2. **한국어 정규화 미강제** (branch ②): OpenAI 프롬프트가 "확인된 정보만"만 지시하고 "입력이 외국어일 수 있으니
   전부 자연스러운 한국어로, 원문 조각·스펙 직역 금지"를 명시 안 함 → 일본어 스펙이 그대로/직역돼 KO 혼재.
   (branch ①(단순 번역 API 배선)은 **아님** — 이미 초안 프롬프트지, 번역 API가 아니다. 감사로 배제.)

## 2) 수리 (서버만 — 확장·번역쿼터·AI예산 불가침)
- `_MARKET_UI_JUNK_RE`(JP/KO/EN **UI 액션·배너만** 좁게: 신고·리뷰·찜·장바구니·쿠폰·포인트·송료무료 등) +
  `_clean_specs_for_draft`/`_clean_keywords_for_draft` — 스펙/키워드에서 UI 쓰레기 행 제거(상품 속성어 サイズ/
  素材/원산지/색상/무게는 **보존**, 오탐 0). `generate_description`이 두 경로(openai·stub) 진입 전 전처리.
- **OpenAI 프롬프트 강화**: "입력이 외국어(일본어 등)일 수 있음 → 결과물은 처음부터 끝까지 **자연스러운 한국어
  판매 문안**, 원문 조각·스펙 직역 금지, 쇼핑몰 UI 문구 무시, 스펙은 한국어로 정리·소구점 문장화."

## 3) 출력 전/후 예시 1쌍 (TSUMUGI, stub 경로 — 결정적)

**BEFORE (수리 전)**
```
■ 특징
· レコード
· 木製
· レビューを見る          ← UI 쓰레기
· 送料無料                ← 배너
■ 옵션·상세
· サイズ: 約30×30×5cm
· 素材: 天然木（オーク）
· 原産国: 日本
· 不適切な商品を報告: する   ← UI 쓰레기(신고 버튼)
· レビュー: レビューを書く   ← UI 쓰레기
· お気に入り: お気に入りに追加 ← UI 쓰레기(찜)
```

**AFTER (수리 후, stub)**
```
■ 특징
· レコード
· 木製
■ 옵션·상세
· カラー: ナチュラル, ブラウン
· サイズ: 約30×30×5cm
· 素材: 天然木（オーク）
· 原産国: 日本
```
UI 쓰레기 4종(不適切な商品を報告·レビュー·お気に入り·送料無料) **전부 제거**. 남은 일본어 스펙은 **stub(키 없음)
한계** — 오너 env는 OpenAI 키가 있어 `_describe_openai` 경로가 강화된 프롬프트로 **일본어 스펙까지 자연스러운
한국어**로 정규화한다(계약: 프롬프트에 한국어 정규화·UI 무시 지시 + 정제 입력 실증).
