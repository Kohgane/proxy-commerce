# v63 STEP1 — 감지 아키텍처 역전: Generic-first, Adapter-augment

## 근본 원인 (팩트 확인)
- 요시다 = 제네릭 카드 휴리스틱 경로 건강(호버/벌크/배지 정상).
- 옛 `kgpFindCards`: **어댑터 우선, 어댑터가 정확히 0건일 때만 제네릭 폴백**. → 어댑터가 부분매치(현행 DOM 일부만 매치)하면 제네릭의 더 넓은 결과가 **억제**됨. 어댑터가 사망(0건)해도 제네릭 폴백은 됐지만, 부분매치 억제 + 테무 SPA(이미지가 `<a>` 미포함)에서 제네릭도 0 → 버튼 미표시.

## 수리
### 1) 감지 역전 (`kgpFindCards`)
- **제네릭을 항상 먼저 실행**, 어댑터(아마존)는 그 다음. `_kgpMergeCards(generic, adapter)`로 병합.
- 상품키 `_kgpCardKey(url)`(아마존 ASIN·테무 goods_id·정규화 URL)로 같은 상품 묶음 → **어댑터 결과가 정밀 보강(덮어씀)**, 제네릭만 잡은 상품은 **유지**.
- → 어댑터 셀렉터 불일치/부분매치가 제네릭 커버리지를 **절대 막지 않음**(폴백 차단 구조 제거).

### 2) 제네릭 앵커 폴백 (`_kgpGenericCards`)
- 테무 등 SPA는 이미지를 `<a>`로 안 감쌈 → `img.closest("a[href]")` 실패. 카드 컨테이너(`[class*=card/item/product/goods]`)의 **상세링크 앵커**로 폴백(상세 href 우선, 없으면 첫 앵커).

### 3) 감지 디버그 패널 (팝업)
- content_script `kgpDetectState` 메시지 → 팝업 `감지 진단` 패널: **호스트·지정여부 · 판정(단일/목록/불능) · 버튼상태 · 카드 감지수(제네릭/어댑터 매치·미스) · 스캔 전체**. 추측 서술이 아니라 실측 → "왜 안 떠?"를 캡처 한 장으로.
