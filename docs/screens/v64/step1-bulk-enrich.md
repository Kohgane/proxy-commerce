# v64 STEP1 — 벌크 상세 보강 (퍼센티식 2단 수집)

## 원인 구조
- 벌크 수집은 **목록 페이지 데이터**(제목·가격·대표이미지)만 저장 — 옵션·상세·리뷰·평점·갤러리는 **상세 페이지**에만 존재. 아마존 벌크 22건이 전건 "옵션·상세·리뷰 누락"인 이유.

## 수리 (2단 수집)
### 1단 — 목록 저장(기존)
- `collectBulk`이 목록 데이터를 즉시 저장하고 서버가 `item_id` 회신. 성공·중복 항목을 `enrichTargets[{item_id, url}]`로 수집(실패는 제외).

### 2단 — 백그라운드 탭 보강(신규)
- `handleEnrichStart` → `_kgpEnrichLoop`: 각 상품 URL을 **백그라운드 탭**(`chrome.tabs.create({active:false})`)으로 순차 방문 → 로드 완료 대기 → content_script `extractMeta`로 옵션·상세·상세이미지·갤러리·리뷰·평점 추출 → 서버 `/api/v1/collect/enrich`로 병합 → 탭 닫기.
- **서버 직접 크롤 없음** — 사용자 브라우저 컨텍스트에서 읽은 값만(차단 리스크 최소, 가짜 성공 0).
- **속도 제어**: 동시 1탭 · 항목당 `_kgpEnrichDelayMs` **3~6초 랜덤** · **실패 1회 재시도** 후 '보강 실패' 정직 집계.
- **진행 UI**: 팝업 `상세 보강 n/총` + **일시정지/중단** 버튼(`enrichPause`/`enrichStop`), 벌크바 상태에도 실시간(`enrichProgress`).

### 서버 `POST /api/v1/collect/enrich` (fill-only)
- 기존 항목을 item_id로 찾아(소유 스코프) 상세 필드 병합:
  - **제목·가격은 기존 우선**(상세 추출이 비면 유지) — fill-only.
  - 옵션·리뷰·평점은 비었을 때 채움, 상세설명은 20자↑ 실텍스트일 때, 상세이미지·갤러리는 **union(순서보존 dedup)**.
- `compute_collect_status` 재계산 → **상태 배지 부분→성공**. 미인증 401·미존재 404.
