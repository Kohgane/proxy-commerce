## 2. 왜 4변형 pc-badge로 '그대로' 축소하면 안 되나
공통 `pc-badge`(on/off/danger/muted 4색)로 단순 축소하면:
- 진행 4단계(신규→결제→준비→배송)가 한 색으로 뭉쳐 **at-a-glance 단계 스캔 상실**,
- danger 3종(반품·교환·환불)은 원래도 색 동일이라 무손실.
→ **라벨은 살아 있어 의미 구분(distinction)은 0 손실**이지만, **진행 단계의 시각적 순서 읽기**를 잃는다.
그래서 단순 축소가 아니라 **① 마켓=색 제거(무손실) + ② 상태=한지 라이프사이클 램프(순서 보존)** 를 제안한다.

## 3. 제안 매핑

### 3-1. 마켓 색상 코딩 → 뮤트 통일 (정보 손실 0)
| 현행 | 제안 |
|---|---|
| 쿠팡=warning / 스스=success / 11번가=danger / 기타=secondary | **전부 `pc-badge-muted`** (라벨이 구분자) |

**구분 손실 0 증명:** 마켓명 텍스트(쿠팡/스마트스토어/11번가/…)가 항상 뱃지 안에 있다. 색은 텍스트와
1:1 중복이었고, 텍스트만으로 완전 구분된다. 색 제거 = 중복 제거(정보량 불변). (카탈로그·마켓 화면
v86-R/S에서 이미 마켓 라벨=뮤트로 통일 — 일관성도 확보.)

### 3-2. 주문 상태 → 한지 라이프사이클 램프 (순서 보존, 신설 토큰)
주문은 **단조 진행 시퀀스**(신규→결제→준비→배송→완료) + **종결 상태**(취소/반품/교환/환불)다.
부트스트랩의 파랑·시안·노랑은 **순서 의미가 없다**. 한지 팔레트로 **먹→금→청록** 진행 램프를 깔면
색 자체가 '얼마나 진행됐나'를 말한다(현행보다 **정보 밀도 ↑**).

| status | 라벨 | 제안 토큰(신설) | 파생(기존 팔레트) | 읽기 |
|---|---|---|---|---|
| new | 신규접수 | `--st-new` | `--muted` #8A8275 틴트 | 시작(중립) |
| paid | 결제완료 | `--st-paid` | `--gold-soft`(금 연) | 진행 ▁ |
| preparing | 상품준비중 | `--st-prep` | `--gold` #C9A24B | 진행 ▃ |
| shipped | 배송중 | `--st-ship` | `--teal` #119A8E | 진행 ▅ |
| delivered | 배송완료 | `--st-done` | `--success` #2E7D5B | 완료 ▇(청록-녹) |
| canceled | 취소 | `--st-cancel` | `--ink-soft` #3A352E 뮤트 | 종결(중립) |
| returned | 반품 | `--st-return` | `--danger` #C2503C | 종결(문제) |
| exchanged | 교환 | `--st-exchange` | `--danger` (라벨 구분) | 종결(문제) |
| refund_requested | 환불요청 | `--st-refund` | `--danger` (라벨 구분) | 종결(문제) |

- 램프 4색(new·paid/prep·ship·done)은 **먹 뮤트 → 금 연 → 금 → 청록 → 청록-녹**으로 **단조 증가**.
  현행 파랑·시안·노랑(무순서)보다 **단계 스캔이 더 정확**.
- 반품/교환/환불은 현행처럼 danger 공유 + **라벨로 구분**(무손실, 현행과 동일).
- 전부 `color-mix`로 은은한 배경 + 토큰 텍스트(하드코딩 hex 0, gogabridj 규칙 준수, 이모지 0).

## 4. 정보 구분 손실 0 — 증명 요약
| 축 | 현행 구분자 | 제안 구분자 | 손실 |
|---|---|---|---|
| 마켓 | 색+이름(중복) | 이름(뮤트) | **0** (색은 중복이었음) |
| 상태 의미(9종) | 색+라벨 | 램프색+라벨 | **0** (라벨 전부 보존) |

→ 어느 축에서도 구분 정보가 줄지 않는다. 진행 순서는 오히려 새로 생긴다.

## 5. gogabridj-design 기준 신설 토큰 (승인 대상)
`app.css :root`에 라이프사이클 램프 토큰 5종 신설 제안(기존 base 색에서 파생, 새 base hue 0):
```
--gold-soft: color-mix(in srgb, var(--gold) 55%, var(--paper));   /* 이미 유사 토큰 있으면 재사용 */
--st-new:      var(--muted);
--st-paid:     var(--gold-soft);
--st-prep:     var(--gold);
--st-ship:     var(--teal);
--st-done:     var(--success);   /* 청록-녹 */
--st-cancel:   var(--ink-soft);
--st-danger:   var(--danger);    /* 반품·교환·환불 공용 */
```
+ 공통 컴포넌트 `.pc-badge-lifecycle`(위 토큰을 `data-st`로 선택)로 orders/cs 재사용.
※ 위 값은 초안 — 승인 시 실제 대비(WCAG AA)·다크 대응까지 확정해 구현 PR에 반영.
