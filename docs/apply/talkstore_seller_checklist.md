# 톡스토어 연동 — 판매자 준비 체크리스트 (K3)

고가브릿지가 **연동대행사로 승인된 뒤**, 첫 매핑 테스트를 하려면 판매자 쪽에서 준비할 것들입니다.
오너와 첫 파일럿 판매자가 순서대로 확인하시면 됩니다.

> 승인 전에는 **아무것도 전송되지 않습니다.** 인증키를 미리 넣어 두셔도 등록은 열리지 않고,
> 화면에는 '매핑 대기'로 표시됩니다. 가짜로 '활성'이라고 하지 않습니다.

---

## 1. 판매자 쪽 선행 조건

| # | 항목 | 확인 |
|---|---|---|
| 1 | **톡스토어 입점 완료** — 스토어가 열려 있고 상품을 올릴 수 있는 상태 | ☐ |
| 2 | **판매자 계정 권한** — API 인증키를 발급할 수 있는 관리자 권한 | ☐ |
| 3 | **사업자 정보 일치** — 톡스토어 입점 사업자와 신청 사업자 정보가 어긋나지 않는지 | ☐ |
| 4 | **대행사 매핑 여력** — 이미 다른 대행사에 매핑돼 있다면 동시 매핑 상한에 걸리는지 | ☐ |

4번은 카카오 정책상 **판매자 한 곳이 동시에 맺을 수 있는 대행사 수에 상한**이 있어서 봅니다.
정확한 수치는 공개 문서 확인 후 확정해 이 문서에 채웁니다(추정으로 적지 않습니다).

## 2. 발급받아 우리에게 넘길 것

| 항목 | 어디서 | 우리 쪽 입력 위치 |
|---|---|---|
| **판매자 API 인증키** | 톡스토어 판매자센터 | 콘솔 → 마켓 연동 → 톡스토어 |
| 스토어 ID(있으면) | 판매자센터 스토어 정보 | 같은 화면 |

- 인증키는 **콘솔에 직접 붙여넣으세요.** 채팅·메일로 보내지 마시고, 스크린샷도 남기지 마세요.
- 저장은 암호화됩니다. 저희 화면 어디에서도 원문이 다시 보이지 않습니다.
- **대행사 앱 키는 판매자가 넣지 않습니다** — 저희 서버가 보관합니다.

## 3. 매핑 요청 양식 (5항목)

대행사 승인 뒤 카카오 쪽에 매핑을 요청할 때 필요한 값입니다. 판매자에게 받아 두시면 됩니다.

| # | 항목 | 예시 |
|---|---|---|
| 1 | 판매자 상호(사업자등록증 기준) | 우주대행 |
| 2 | 사업자등록번호 | [판매자 기입] |
| 3 | 톡스토어 스토어명 / 스토어 ID | [판매자 기입] |
| 4 | 담당자 이름·연락처 | [판매자 기입] |
| 5 | 매핑 요청 대행사 | 고가브릿지 (고가네) |

## 4. 첫 매핑 테스트 진행 순서

1. 판매자가 인증키를 콘솔에 입력 → 상태가 **미매핑 → 매핑 대기**로 바뀝니다.
2. 카카오 쪽 매핑 승인이 확인되면 상태가 **활성**이 됩니다.
   (승인 전에는 키가 다 있어도 활성으로 바뀌지 않습니다.)
3. **카나리 1건**부터 올립니다 — 한 상품만 등록해 눈으로 확인한 뒤 나머지를 진행합니다.
   쿠팡·스마트스토어에서도 같은 순서로 했습니다.
4. 등록이 거부되면 **응답 원문 그대로** 보여 드립니다. 무엇이 왜 막혔는지 보고 고칩니다.

## 5. 지금 확정되지 않은 것 (정직 표기)

아래는 **공개 문서를 확인한 뒤** 채웁니다. 지금 추정해서 적지 않습니다.

- 상품 등록 API의 필수 필드 목록과 카테고리 체계
- 이미지 규격(장수·해상도·형식)
- 호출 한도(초당/일일)
- 동시 매핑 가능한 대행사 수의 정확한 값
- 주문·문의 조회 API의 응답 구조

이 다섯 가지가 확정되면 쿠팡·스마트스토어와 같은 방식으로 **필드 매핑 표**를 만들고,
그 표가 나온 뒤에야 페이로드를 짓습니다. 순서를 뒤집으면 거부만 반복합니다.

## 오너 액션 요약

1. 대행사 신청서 제출(소개서 = `docs/apply/gogabridj_intro_kakao_v1.pdf`)
2. 승인 통보 오면 → 서버에 대행사 Admin키 설정
3. 파일럿 판매자에게 위 **2·3장** 전달 → 인증키 발급·매핑 요청
4. 공개 문서 원문 확보 → 필드 매핑 표 작성 → 그다음 페이로드
